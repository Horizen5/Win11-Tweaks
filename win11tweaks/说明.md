# Win11 顺手设置 · 原生 C 单文件版 v2.0.0

把原来那套「PowerShell + 多个 .ps1 + 运行.cmd」的方案，重写成一个 **原生 C 单文件 exe**，
并新增了 **导出 / 导入配置** 能力（换新电脑一键还原）。

- 产物：`dist\Win11Tweaks.exe` —— **237,568 字节（232.0 KB）**，x64 原生，静态链接，**零运行时依赖**
- 依赖 DLL：仅 6 个系统自带（KERNEL32 / USER32 / ADVAPI32 / SHELL32 / GDI32 / COMDLG32）
- 双形态：**双击 = 图形界面**，带参数 = 命令行

## 二、命令行用法

```
Win11Tweaks.exe [命令] [参数]
```

不带任何参数时**打开图形界面**。

### 命令

| 命令 | 简写 | 说明 |
|---|---|---|
| `--apply` | `-a` | 按 `settings.ini` 应用设置（**默认行为**） |
| `--export [文件]` | `-e` | 读取当前系统真实状态，导出为配置文件（缺省写到程序目录） |
| `--import <文件>` | `-i` | 导入配置文件并恢复：**先出差异 → 再自动备份 → 最后写入** |
| `--diff <文件>` | `-d` | 只显示「当前系统 vs 配置文件」的差异，**不写任何东西** |
| `--status` | `-s` | 列出全部 **51 个**受管注册表值的当前状态 |
| `--backup` | | 只把当前状态备份成还原点 |
| `--restore <文件>` | `-r` | 从某个还原点文件恢复（同样先出差异） |
| `--gui` | `-g` | 强制打开图形界面 |
| `--help` | `-h` / `/?` | 显示帮助 |
| `--version` | | 显示版本号 |

### 通用选项

| 选项 | 说明 |
|---|---|
| `-y` / `--yes` | 不再询问，直接执行 |
| `-n` / `--dry-run` | 只报告将要做什么，不真正写入 |
| `--no-backup` | 本次跳过自动备份 |
| `--no-elevate` | 不自动提权（去箭头 / 去盾牌需要写 HKLM） |
| `--ini <文件>` | 指定 `settings.ini` 的路径 |

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 运行时失败 |
| `2` | 参数错误（**认不出的选项一律退 2，绝不退化成默认 apply**） |
| `4` | 请求转图形界面 |

### 例子

```bat
Win11Tweaks.exe                          :: 打开图形界面
Win11Tweaks.exe --status                 :: 看当前 51 个值
Win11Tweaks.exe --apply -n               :: 预演一遍，不写入
Win11Tweaks.exe --export D:\我的配置.json :: 导出当前设置
Win11Tweaks.exe --diff  D:\我的配置.json  :: 看差在哪
Win11Tweaks.exe --import D:\我的配置.json -y
Win11Tweaks.exe --backup                 :: 打一个还原点
Win11Tweaks.exe --restore backups\backup_20261006_165530.json
```

## 三、换新电脑：三步还原

> 这是本次新增的核心功能。**只导本工具管辖的设置**，不碰系统其它配置。

```bat
:: ① 旧电脑：导出当前真实设置（会自动带上机器名 / 系统版本 / 时间戳）
Win11Tweaks.exe --export

:: ② 把生成的 profile_20261006_165529.json 拷到新电脑（U盘 / 网盘都行）

:: ③ 新电脑：先看差异，再导入
Win11Tweaks.exe --diff "D:\profile_20261006_165529.json"
Win11Tweaks.exe --import "D:\profile_20261006_165529.json"
```

导入时的安全设计：

1. `--diff` 会逐项列出「当前值 → 目标值」，确认无误再执行；
2. `--import` 执行前**自动**把当前状态写成还原点（`dist\backups\backup_*.json`）；
3. 只写**有差异**的项，相同的值一概跳过（零冗余写入）；
4. 如果改坏了，`--restore` 那个还原点即可精确回到导入前的样子。

导出的配置文件是带 BOM 的 UTF-8 JSON，形如：

```json
{
  "format": "Win11Tweaks.Profile",
  "version": 1,
  "note": "本文件由 Win11Tweaks 导出。导入时只写差异项，且会先自动备份当前值。",
  "exported": "2026-10-06T16:26:23+08:00",
  "machine": "MY-PC",
  "user": "MyUser",
  "os": "Windows 11 Build 26300",
  "count": 51,
  "values": [
    {
      "id": "TaskbarAlignLeft",
      "label": "任务栏图标靠左",
      "hive": "HKCU",
      "key": "Software\\Microsoft\\Windows\\CurrentVersion\\Explorer\\Advanced",
      "name": "TaskbarAl",
      "type": "REG_DWORD",
      "exists": true,
      "data": 0
    }
  ]
}
```

`exists: false` 表示该值当前**不存在**（导入时会精确删除），这是「删除 → 恢复」能完全还原的关键。

## 六、性能对比

均为本机实测（测试机 / Ryzen 5 7500F / Win11 26100），每项 **20 次**。

| 项目 | 平均 | 中位 | 最慢 | 慢于 200ms |
|---|---|---|---|---|
| **新** `--version` | 15.4 ms | 15.3 | 17.6 | 0 |
| **新** `--status`（读 51 个值 + 输出） | 16.8 ms | 16.8 | 17.7 | 0 |
| **新** `--apply --dry-run` | 17.4 ms | 17.5 | 18.2 | 0 |
| **新** `--export` | 16.6 ms | 16.5 | 17.5 | 0 |
| **新** `--backup` | 17.3 ms | 17.1 | 18.9 | 0 |
| **新** `--diff` | 16.6 ms | 16.6 | 17.4 | 0 |
| **新** `--import`（同源配置，差异 0） | 16.7 ms | 16.6 | 19.0 | 0 |
| 旧 PowerShell 5.1 冷启动（空脚本） | 134.5 ms | 134.8 | 137.7 | 0 / 5 |
| 旧 PowerShell 读 51 次注册表（等效工作量） | **299.5 ms** | 300.5 | 303.5 | **5 / 5** |

**结论：**

- 等效工作量（读 51 个注册表值）从 **299.5 ms → 16.8 ms**，**快约 17.8 倍**
- 最坏情况（旧方案 5/5 全部超过 200 ms）在新方案下 **20 次全部低于 19 ms**，波动几乎为零
- 启动开销 15 ms 中有相当一部分是控制台子系统（conhost）的固定成本；换来的是
  **PowerShell 里能正确等待、能重定向、能拿到退出码**（见第七节）

## 七、本轮修复的两个关键缺陷

这两个都不是「优化」，而是**真实的、能复现的 bug**，修复前工具处于「约 1/3 概率崩溃」的状态。

### 缺陷 1（严重）：`ProfileFree()` 野指针 → 堆损坏

**现象**：`--diff` / `--import` 有约 1/3 概率「卡住 1 ~ 4.6 秒」，随后正常返回。
用 `QueryPerformanceCounter` 父子双日志埋点后发现：**卡住的那次，函数尾巴整段消失**。

**排查链**：
埋点确认卡在 `cli.tail.free_d` → 排除文件系统/杀软（PowerShell 读同文件 0.1 ms）→
最小对照程序读同文件 30 次零卡顿 → 分类矩阵证明「**只有"成功读到文件"才卡**」→
子进程真实寿命 ≈ 父进程等待时间（排除父进程等待假象）→ **采集退出码 = `0xC0000374`（堆损坏）/
`0xC0000005`（访问违例）** → 用 MSVC AddressSanitizer 精确定位。

**ASan 报告**：

```
ERROR: AddressSanitizer: attempting free on address which was not malloc()-ed:
        0xbebebebebebebebe
    #1 ProfileFree   src/tweaks.c:386
    #2 CliMain       src/cli.c:412
SUMMARY: AddressSanitizer: bad-free src/tweaks.c:386 in ProfileFree
```

（`0xBE` 是 ASan 给未初始化堆填的标记值 —— 说明 `free()` 的是**从未被赋值**的指针。）

**根因**：`ProfileLoadJson()` 用 `wt_alloc` 拿 `pf->vals` 后**只写了 `opIdx`，忘了清零**；
而解析循环对 JSON 里 `exists == false` 的项直接 `continue`，从不碰 `sz` / `bin` 两个指针。
于是这两个指针保留着堆里的陈旧垃圾值，`ProfileFree()` 的 `free()` 把堆踩坏。
对比 `TweakSnapshot()` 走 `RegReadOp()`（首句就是 `memset(st, 0, sizeof(*st))`），所以永远安全 ——
这也解释了为什么只有「读文件」这条路会崩。

**修复**：新增唯一构造入口 `ProfileNew()`，同时清零 `pf` 与 `pf->vals`，两处调用点全部改用它；
函数头写清事故注释防复发。

```c
Profile *ProfileNew(void)
{
    Profile *pf = (Profile *)wt_alloc(sizeof(Profile));
    memset(pf, 0, sizeof(*pf));
    pf->count = g_opCount;
    pf->vals = (ValState *)wt_alloc(sizeof(ValState) * (size_t)g_opCount);
    memset(pf->vals, 0, sizeof(ValState) * (size_t)g_opCount);
    return pf;
}
```

**验证**：ASan 13 个入口 × 5 次 = **0 发现**；ASan 5 个命令 × 8~12 次 = **0 发现**；
正式版 150~200 次压力 = **0 慢、0 非零退出**。

### 缺陷 2：`SUBSYSTEM:WINDOWS` 导致 PowerShell 不等待、拿不到输出

**现象**（三个症状同源）：

| 症状 | 表现 |
|---|---|
| 重定向为空 | Bash `> 文件` 得 1114 字节 ✅，PowerShell `> 文件` 得 **0 字节** ❌ |
| 拿不到退出码 | `$LASTEXITCODE` 为空 |
| 输出迟到 | 上一次运行的输出，在**下一次**运行时才冒出来 |

**根因**（两个叠加）：

1. **PowerShell 5.1 按 PE 子系统决定是否等待子进程**。`SUBSYSTEM:WINDOWS` ⇒ PowerShell
   甩手就走（实测裸调用 3.3 ms 返回，而真实工作量约 10 ms；对照 `powershell.exe` 122.4 ms
   是正常等待的）。既然不等待，自然拿不到退出码，重定向文件也来不及写完。
2. `ConInit()` 把「是否重定向」判在 `AttachConsole` **之前**，但 `g_out` 却是在
   `AllocConsole()` **之后**才取 —— 而 **`AllocConsole` 会重置标准句柄**，
   重定向句柄被丢掉，输出全灌进了那个看不见的新控制台。

**修复**：

- 子系统改 `SUBSYSTEM:CONSOLE`，入口改 `int main(void)`；
  GUI 形态下自己调 `FreeConsole()` 脱离控制台（`DetachConsoleForGui()`：先用
  `GetConsoleProcessList` 判断这个控制台是不是自己新建的 —— 是自己的就 `SW_HIDE` 隐藏，
  是别人（比如从 cmd 启动）的就只脱离、不留空窗口）。
- `ConInit()` 在 `AttachConsole` / `AllocConsole` **之前**捕获并保存 `hOrigOut`，
  重定向时优先使用它。

**验证**：裸调用 15.4 ms 且 `$LASTEXITCODE=0`；`--status > p1.txt` 得 8280 字节；
`--help > p2.txt` 得 1366 字节；`--totally-bogus`（不存在的选项）退出码 **2** 正确传递。

| 问题 | 处理 |
|---|---|
| 重定向输出中文乱码（PowerShell 得到 UTF-16LE 乱码） | `ConWrite()` 按目标分流：**真实文件 → UTF-8 + BOM + CRLF**；**管道 → `GetOEMCP()`**（cmd/PowerShell 按 OEM 代码页解码子进程输出） |
| `SetConsoleOutputCP(CP_UTF8)` 污染用户控制台代码页 | 直接删掉该调用（输出走 `WriteConsoleW`，本来就与代码页无关） |
| `WtTrace` 里 `wt_strlcat` 参数顺序写反 | 修正 |
| 父子进程共用同一日志文件互相覆盖 | 改为父子分写 `wt_parent.log` / `wt_trace.log` |
| `(PFN_DPIAWARE *)` 函数指针类型错误 | 修正为 `(PFN_DPIAWARE)` |

## 八、一个被删掉的 hack：为什么本程序能写受保护的值

Win11 有个 **UCPD 驱动**（`C:\Windows\System32\drivers\ucpd.sys`），会拦截对
`TaskbarDa` / `SearchboxTaskbarMode` 等值的写入以防止第三方篡改。
原方案的做法是「**复制 `reg.exe` 改名再执行**」来绕过。

本次从驱动二进制里提取出了它的黑名单 —— **14 个纯文件名字符串，不校验签名**：

```
reg.exe  regedit.exe  regini.exe  powershell.exe  pwsh.exe  cmd.exe  mshta.exe
rundll32.exe  wscript.exe  cscript.exe  InfDefaultInstall.exe  wmiprvse.exe
dllhost.exe  bssafe.exe
```

**匹配方式只是「进程文件名」，不校验签名。** 因此自有进程名 `Win11Tweaks.exe` 天然不在名单内，
可以直接写这些值 —— 整个「复制 reg.exe 改名执行」的 hack **被彻底删除**，
不再往磁盘丢临时可执行文件，也不再触发杀软。

## 十一、已知说明与注意事项

1. **`--version` 在 bash 管道里会显示乱码** —— 这不是 bug。bash 管道走的是
   `GetOEMCP()` 路径（本机为 932/日文），而 bash 按 UTF-8 解读。用 cmd / PowerShell
   或重定向到文件都正常。
2. **去箭头 / 去 UAC 盾牌需要管理员权限**（写 `HKLM`）。程序会按需自动提权，
   可用 `--no-elevate` 关闭。
3. **改完任务栏 / 桌面图标后需要重启资源管理器或注销**才会看到效果，这是 Windows 的限制。
4. **导入不认识的开关**：JSON 里出现本版本不认识的 `id` 会被跳过并记日志，不会报错中断。
5. **`Win10ContextMenu` 是 Win11 专用**，Win10 上会自动跳过（`Win11 优先` 标记项）。
6. 本工具**只动上表 51 个值**，不碰系统其它配置；`--restore` 可精确回滚。
